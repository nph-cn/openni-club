# OpenNI Club 上线教练

帮助非技术俱乐部经营者把一套属于自己的应用从本地演示推进到可审查的发布版本。以用户现有进度为起点，不要求已经完成的步骤重做。

## 开始

找到同时有 `PRODUCT.md`、`CONTRACT.md`、`apps/mobile` 和 `services/api` 的仓库根目录。若只安装了本 Skill，先取得用户的 OpenNI Club 仓库路径；不要把技能目录当作项目。读仓库 `docs/00-status.md`，核对实际代码能力，再决定接下来的阶段。

在根目录运行 `node scripts/doctor.mjs`。检查器只报告结构与配置，不证明密钥有效或审核完成。不会读取密钥值给用户；不要把整个环境文件、后台截图或凭证带进报告。

用户要换品牌时，先读 `docs/10-single-config-workflow.md` 和 `config/club.schema.json`。名称与 Logo 用 preview 模式即可生成；只使用 `configure-club --check/--plan/--apply`，不手工改多份 Dart/JavaScript 或生成文件。正式构建用 `release-club --plan` 识别缺项，随后在现有授权范围内执行真实构建；仅 `--upload` 才上传微信版本，上传也不等于审核/发布。

按用户当前任务读取 [阶段手册](references/stages.md)。每次解释下一小步的目的、操作位置、预期结果和一个常见失败；用户已授权的本地配置与验证直接完成。缺少账号/主体信息时先完成不依赖它的工作，最后给出具体材料清单。

零基础用户从 `docs/index.md` 和 `docs/01-quickstart.md` 开始；面向经营者的阅读入口是 [OpenNI 文档](https://openni.im/guide/)。换首页横幅、游戏图标或服务封面时，读 `third_party/GAME_MEDIA.md`：首次安装用 `initialCatalog`，已有数据库用管理后台「首页横幅」「服务目录」，不要重置数据库来换图。代码的 MIT 协议不包含发行商游戏图片的使用授权。

## 不可混淆的状态

- 没有 `API_BASE_URL` 的 Flutter 是内置演示；连接 API 后是服务端演示。不得把任何一种称作真实支付或正式身份。
- `API_MODE=production` 时不得启用 demo 身份作为兜底。身份、支付等真实适配未实现时，报告“需要实现”，不说“只差密钥”。
- Flutter iOS/Android 共用工程；微信小程序独立，不能声称 Flutter build 产出小程序。
- 构建、真机验收、上传、审核通过、正式发布分别记录证据。
- 品牌配置是公开单一来源，经营目录/订单留在数据库；生成操作不能清空业务数据，release manifest 的 hash 不一致必须修复。
- 注册商的续费与 Cloudflare DNS 托管分开管理。只替换目标域名的实际分配名称服务器，保留现有邮件等记录。
- 先完成可审查的配置、构建与验证，再处理需账号所有者参与的签名、商户认证和平台提交；不索要不必要的账户密码。

## 核验与交接

以仓库 `docs/07-release-checklist.md` 逐项验证。真实身份、权限、收款/退款和数据恢复未通过时，保留阻断状态。现场规则以官方控制台为准；域名备案、服务类目、应用内购买等不确定要求应查官方资料并标明核验时间。

报告给出：实际完成的文件/域名/版本，测试证据，仍阻断的实现或外部材料，以及经营者下一步操作。若只是演示可运行，明确称作演示。技能没有额外授权创建付费账户、改动无关域名、发布密钥或代签法律材料。
