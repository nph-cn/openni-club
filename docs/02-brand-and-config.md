# 品牌与资料

使用一份 [俱乐部配置](../config/club.example.json) 管理品牌。先准备名称和 Logo，确认预览，再补正式发布资料。不需要修改 Dart、JavaScript、Gradle 或 Xcode 源码来更换名称、图标和包标识。

## 1. 在网页填写品牌

打开 [品牌配置页](https://openni.im/studio/)，按顺序填写：

1. 在「品牌」上传自己的 Logo，填写俱乐部名称；简称、主色和更多品牌资料按需填写。
2. 查看右侧 App 的名称和配色。需要刷新时点击「更新预览」。
3. 在「经营资料」填写自己的主体、客服和公开信息。
4. 在「第三方集成」填写准备好的平台身份和接口配置；尚未开通的服务留空。
5. 到「导出」下载配置包，解压后再放入仓库。

**检查结果：** 配置包中包含 `club.json` 和 `assets/`。如果填写了服务端密钥，它们在独立的 `server.env` 中，不应出现在公开的 `club.json`。

网页不会直接修改已运行的服务器。把配置包应用到项目的步骤见 [生成应用配置](10-single-config-workflow.md)。

## 2. 区分品牌与经营内容

| 内容 | 修改位置 / 做法 |
| --- | --- |
| 名称、Logo、主色、介绍 | `brand`；生成器同步 Flutter/小程序/后端与原生图标 |
| 经营主体、客服、政策 | `operator` / `legal`；公开页面由生成器输出，正式内容由经营者确认 |
| API 与网站地址 | `endpoints`；发布脚本自动传公开构建参数 |
| 应用标识、版本、公开 AppID | `distribution`；生成原生配置和小程序项目配置，后续保持已发布的应用身份 |
| 服务、成员、公告与排班 | 日常在后台维护数据库；`initialCatalog` 只用于首启，不覆盖现有用户或订单 |
| 微信公众平台上的展示名称/头像/类目 | 在自己的微信账号提交修改；代码生成不能代替平台审批 |

改名后先查看 `--plan` 差异，再重新生成和构建；安装图标与系统显示名需要发布新版。保留 MIT 版权与许可文本。若已有真实订单，价格调整只影响新订单，历史金额快照不变。

## 3. 配置游戏图片和首页横幅

游戏图片、服务封面和首页横幅属于经营内容。填写自己有权使用、可公开访问的 HTTPS 图片地址；服务端密钥或带临时授权参数的私密地址不适合作为公开封面。

| 位置 | 配置字段 | 显示内容 |
| --- | --- | --- |
| 服务列表 | `coverUrl` | 服务封面 |
| 游戏入口 | `gameIconUrl` | 游戏图标 |
| 服务详情 | `bannerUrl` | 服务横幅 |
| 首页横幅 | `banners[].imageUrl` | 首页展示图片 |

首次安装可以在 `initialCatalog` 中准备这些内容；部署后打开运营后台的「首页横幅」，填写标题、图片 HTTPS 地址、服务编号或游戏、顺序，再保存。服务编号与游戏至少填写一项；服务编号必须对应已有服务，优先于游戏跳转。游戏名称与服务中的 `game` 完全一致。初始目录只写入新数据库，重新生成品牌不会覆盖现有服务或横幅。具体字段见 [生成应用配置](10-single-config-workflow.md)。

更换后打开 App 与小程序，检查图片是否能加载、主体是否被裁掉、点按横幅是否打开对应服务。图片版权与代码的 MIT 许可证分别处理，使用自己的授权素材替换示例图片。仓库图片的来源见 [素材清单](../config/media.sources.json)，使用范围见 [图片授权说明](../third_party/GAME_MEDIA.md)。

## 4. 保存服务端密钥

Flutter `dart-define`、网页 JavaScript、小程序代码都可被用户获取，不能保密。它们只适合放 API URL、AppID、公开品牌和特性开关。

服务器 `.env` 或宿主机密钥管理存放 `ADMIN_TOKEN`，已接入的微信 AppSecret、商户私钥、API v3 Key 和未来短信密钥也只放服务端。不要通过二维码、接口响应、截图或日志输出这些值。

发布后检查 App 中不再出现“北岸电竞”、示例联系方式或误导性的“已支付”描述。生成新的页面截图，把它们和版本号一起保存，方便审核和后续维护。
