# 让 AI 带你完成部署

仓库附带 `skills/openni-launch/`，它保存 OpenNI 的阶段顺序、配置边界和验收方法。它不是一键代办所有平台账号的工具，也不会保管你的私钥。

## 不安装也能用

在支持读取本地文件的 AI 编程助手中打开本仓库，输入：

> 请读取 skills/openni-launch/SKILL.md，使用 OpenNI Launch Skill 检查这个仓库。我是第一次部署，请先帮我跑通本地演示，然后逐步替换为自己的俱乐部。

如果已经有一个阶段完成，可直接说：

> 使用 openni-launch，我的 API 已部署到自己的 HTTPS 域名，接下来准备微信小程序体验版。请检查实际配置和缺少的功能，列出每一步的通过标准。

## 安装到 Codex

把完整的 `skills/openni-launch` 文件夹复制到 Codex 的个人技能目录（通常是 `~/.codex/skills/`），保留 `SKILL.md`、`references`、`agents` 的层级。在新会话中使用 `$openni-launch`，并告诉助手你的 OpenNI 仓库位置。

技能依赖仓库中的最新 `docs/` 和 `scripts/doctor.mjs`；因此只复制技能而不下载项目不能启动应用。更新仓库时同步技能，避免旧教学指向新版本中已变更的路径。

## 你应该拿到什么结果

助手先说明现在是本地演示、服务器演示还是正式准备阶段；完成授权范围内的修改和检查；最后给出实际文件/版本、测试结果和仍缺少的外部材料。不要接受只有“成功”“已上线”而没有实际运行或平台状态证据的答复。

需要填密钥时，直接在本地环境文件或供应商的秘密配置中填写。可以让助手验证“是否配置”，不必把密钥明文复制到聊天。若功能尚未适配，助手应明确指出需开发的代码，不能以补填环境变量替代实现。
