# 手机竞品流程走查与 OpenNI 改进顺序

走查日期：2026-11-23。通过用户提供的 iPhone 镜像，实际浏览了“怪兽易游”的首页、分类、商品详情、提交订单、陪玩列表与主页、消息、我的和订单空态。没有提交订单、付款或体验履约，因此以下只描述可见界面和交互；价格、在线状态、评价与履约承诺没有独立核验。竞品视觉素材仅作研究，不进入 OpenNI 代码或截图。

## 可见流程

| 步骤 | 实际观察 | 对 OpenNI 的设计判断 |
| --- | --- | --- |
| 找到服务 | 首页先选游戏，再看横向服务分类和双列商品；分类页用左侧类目和右侧商品网格。 | 保留游戏上下文，让“按服务找”和“按成员找”两条入口清楚汇合；商品卡只放购买决策需要的价格单位与规则。 |
| 理解商品 | 详情页有大图、价格、说明和底部固定下单动作。 | 详情先解释服务内容、时长、履约条件和真实价格，不用免责声明代替清晰规则。 |
| 找到成员 | 陪玩列表能按游戏与人群浏览；成员主页集中展示介绍、能力和作品，底部进入点单。 | OpenNI 的成员主页应先让用户选该成员实际提供的服务，再进入预约；在线、评分、段位和语音等信息须有真实数据源。 |
| 核对订单 | 提交页把商品、接单方式、规格、游戏 ID、优惠和应付总额放在一处，底部固定结算动作。 | 当前固定价服务先显示明确的商品与费用快照、联系方式和下一步。只有后端具备报价、优惠和游戏 ID 字段时，才加入对应表单与价格计算。 |
| 跟进结果 | 底部有消息和我的订单入口；订单列表有状态切换与空态。 | 下单后应把待派、待接、已排期、服务中、待确认和售后状态说清，并给用户可执行的下一步。 |

## 当前实现与优先级

OpenNI 已有游戏切换与搜索、服务详情、成员列表与主页、预约核对、订单快捷入口、通知分类和订单状态。缺口集中在流程衔接和交易信息，而不是增加首页装饰。

1. **P0：成员到服务的选择。** 成员主页不能默认选 `services.first`。展示该成员可提供的服务、价格单位与适用游戏，由用户点选后带 `playerId`、`serviceId` 进入预约。
2. **P0：预约核对。** 明确列出所选服务、成员或俱乐部分配方式、时长、应付金额和真实提交结果。显示的总价必须与服务端订单报价一致；没有支付联调时不得写“支付成功”。
3. **P1：业务字段。** 按真实 SKU 与后端能力补区服、设备、人数、时长/目标、游戏 ID 模板和费用项。字段需随订单保存快照，供派单、售后与复购使用；具体建模见 [三角洲服务目录](02-market-reality.md)。
4. **P1：履约反馈。** 订单详情用一条时间线连接派单、成员接单、开始、交付和确认。异常状态提供联系运营、换人或售后动作。
5. **P2：个性化与营销。** 收藏、卡券、成员语音、排行榜和推荐只有在数据、权限、运营维护与无障碍方案就绪后再加入。竞品的主题色、IP 形象、卡片图案和宣传措辞都不作为 OpenNI 的设计素材。

验收时分别走“服务先行”和“成员先行”两条路径，覆盖无可约成员、无可用服务、价格变化、订单提交失败和首次无订单。用真实运行界面更新图库；不以静态稿代替可操作状态。
