`API_MODE=production` 关闭演示登录；真实登录需服务端微信或腾讯云短信配置，微信收款还需账号关联和独立启用支付开关。适配器已通过模拟网络及真实 RSA/AES 加解密测试，尚未使用该俱乐部的真实商户凭证完成交易。环境检查会报告剩余生产阻断项；不要通过改成 demo 绕过。配置步骤见 [微信适配教程](09-wechat-adapters.md) 与 [手机号登录教程](11-phone-auth.md)。

「构建成功」表示代码能编译；「真机通过」表示对应设备上跑通指定流程；「审核通过」只能由平台审核结果证明；「收款可用」必须有真实订单、验签及对账证据。发布报告应分别写这四项，不合并成“全部完成”。

本轮详细证据：[功能与集成回归](qa/2026-11-16-api-integration-review.md)、[界面与截图验收](qa/2026-11-16-ui-review.md)。

## 后续版本的验收目标

1. 身份：微信真机登录、真实短信送达、过期会话、账号关联与注销验收。
2. 支付：确认支付方式适合真实业务；完成真实收款、全额退款、手动查单/退款同步联调，建立日常账单核对制度（尚无自动账单下载任务）。
3. 运营：把已实现的排班、派单、交付、争议及分成接口在三角色界面中完整验收；补齐实际客服流程。
4. 社交：如果开放用户内容，先实现举报、屏蔽、审核和联系渠道，再开放发帖/聊天。
5. 发布：自有签名与正式域名的 iOS、Android、小程序真机测试，备份恢复演练。
