# 俱乐部工作台

运行仓库构建后，打开 `/admin/`。默认读取 `demo-snapshot.json`，所有改动按钮保持禁用。快照由后端脚本通过真实 HTTP 角色流程生成，不含密钥或真实客户资料。

在「连接与集成」输入自己的 `/api/v1` 地址和服务器 `ADMIN_TOKEN`。远程地址必须使用 HTTPS，本机可以使用 HTTP。令牌仅存当前页面内存；刷新页面或断开连接后清除。服务器须将工作台域名加入 `CORS_ORIGINS`。浏览器自身可能询问是否保存密码，请勿保存共享管理员令牌。

工作区包括待办、派单、订单与时间线、成员排班与邀请、收益账本与转账凭据、售后、服务规格、公告、品牌配置和连接状态。品牌由生成配置管理；运营内容由后端数据库管理。

成员先在客户端登录，再接受运营生成的一次性邀请。派单会校验排班和冲突。结算只记录外部转账凭据，工作台不会自动打款。真实退款调用微信商户接口，结果以服务端核验为准。

服务规格使用表单编辑名称、价格、时长和终端；可展开独立服务规则覆盖服务默认值。当前履约只支持一位服务成员，多人规格由后端拒绝下单。

`screenshots/manifest.json` 现引用2026-11-16通过 CUA 在本机 Chromium 拍摄的12张 JPG：11个导航工作区及订单详情。拍摄对象为只读 demo；尺寸从图片文件读取，不推断设备缩放倍率。服务、横幅与公告截图在异步内容加载完成后重新拍摄。旧 PNG 保留作历史记录，清单不再引用；图片没有重绘或拼接。

此前功能验证使用隔离的内存演示后端，覆盖连接/刷新清除令牌、派单进入待接单、邀请码、排班保存、服务规格保存、人工凭据写入、只读预览及折叠菜单。本轮截图更新只记录只读界面验收，不重新声称上述写入流程已测。真实商户退款和支付未在浏览器中执行。纯函数验证：`node --test scripts/test/admin-ui.test.mjs`。
